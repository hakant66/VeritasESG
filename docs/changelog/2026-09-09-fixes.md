# Code fixes — 9 September 2026

Summary of database, migration, and application-layer changes made during today’s review and follow-up work on the **governanceiq-sql** repository.

## 1. PostgreSQL migration deploy safety

**Problem:** `prisma/migrations/` contains **MySQL** DDL while `prisma/migrations-postgresql/` contains **PostgreSQL** DDL. Running `npm run db:deploy` against Postgres could apply the wrong engine’s migrations.

**Fix:**
- Added [`prisma/migrate-deploy.mjs`](../../prisma/migrate-deploy.mjs) — reads `provider` from `schema.prisma`, validates `migration_lock.toml`, and runs `prisma migrate deploy` from a temporary directory using the correct migration folder.
- Updated [`package.json`](../../package.json): `db:deploy` now calls this script instead of bare `prisma migrate deploy`.

**How to use:**
```bash
npm run db:provider postgresql
export DATABASE_URL=postgresql://...
npm run db:deploy
```

## 2. Metric entries — facility scoping and SQL parity with Mongo

**Problem:** Mongo uses a **sparse unique** index on `(customerId, year, metricDefinitionCode, facilityId)` — uniqueness applies only when `facilityId` is set. On Postgres, empty string `''` and `NULL` were treated inconsistently, allowing duplicate “company-wide” rows and ambiguous upserts.

**Fix:**
- [`server/data/emissionsSql.ts`](../../server/data/emissionsSql.ts):
  - `normalizeFacilityId()` — empty/whitespace `facilityId` stored as `NULL`.
  - Upsert lookup matches legacy `NULL` and `''` rows when no facility is selected.
  - Handles concurrent create races via `P2002` → retry update.
- [`prisma/sql/pgvector-and-partial-indexes.sql`](../../prisma/sql/pgvector-and-partial-indexes.sql) and [`prisma/migrations-postgresql/1_pgvector_and_partial_indexes/migration.sql`](../../prisma/migrations-postgresql/1_pgvector_and_partial_indexes/migration.sql):
  - Per-facility partial unique index excludes empty strings:  
    `WHERE "facilityId" IS NOT NULL AND "facilityId" <> ''`
  - **No** company-wide unique index — aligns with product rule: one row per facility **plus** optional consolidated (NULL facility) rows for the same metric.
  - Idempotent `DROP INDEX IF EXISTS metricentries_companywide_unique` if a draft index was applied earlier.
- [`prisma/schema.prisma`](../../prisma/schema.prisma) — comment updated to describe sparse/per-facility behaviour.

**Applied on local Postgres:** `sql:extras` / partial-index SQL was run against `governanceiq-postgres-1` (port 5442).

## 3. ETL reference map — assignment and answer question IDs

**Problem:** [`server/data/migration/schemaMap.ts`](../../server/data/migration/schemaMap.ts) mapped `questionIds` / `questionId` to template **`questions`**. In the app, assignments and answers use **project question** IDs (`projectQuestions` collection).

**Fix:** Updated `arrayReferences` / `references` targets:
| Collection | Field | Old target | New target |
|------------|-------|------------|------------|
| assignments | `questionIds` | questions | **projectQuestions** |
| answers | `questionId` | questions | **projectQuestions** |
| answerVersions | `questionId` | questions | **projectQuestions** |

This improves Phase 0 audit dangling-ref checks and ETL metadata accuracy. IDs that are already Mongo `_id` hex values continue to migrate unchanged.

## 6. Review findings — not fixed today (backlog)

These were identified in the SQL/database review but left for a later pass:

- No database **foreign keys** (intentional for ETL; orphan rows possible).
- **Racey upserts** on some non-metric paths (`findFirst` + `create` without unique constraint).
- **`legacyFirebaseId`** not unique — duplicate legacy IDs resolve arbitrarily.
- ETL **`createMany({ skipDuplicates: true })`** is insert-only on re-run.
- **Float** columns for money/emissions (precision drift vs `Decimal`).
- **OTP TTL** relies on periodic cleanup, not DB expiry.
- **pgvector** dimension hardcoded to 768 in migration SQL vs runtime config.
